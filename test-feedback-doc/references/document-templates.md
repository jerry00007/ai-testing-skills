# 文档骨架模板

三种文档类型的章节骨架，取自 2026-09 竖版视频组卡项目实战验证版本。按项目裁剪。

## 1. 需求大回归版（用户要求"从需求出发"时用）

```markdown
# 测试反馈-{项目}-{YYYYMMDD}-需求大回归

> 来源：`{PRD文件名}` 需求逐条驱动
> 本轮：{回归轮次+时间} + {补充项}
> 环境：引擎 {commit}@{IP} ｜ 召回 {commit}@{IP} ｜ 设备 {id}
> 脚本：{脚本清单}

## 一、一句话结论
**{有条件 Go / 有条件 No-Go / Go}**：{核心论据一句话}；{阻塞项列表}——{N}项闭环前{不}上线。

## 二、需求逐条验证总表（PRD 原文 → 结论 → 数据）
| # | 需求原文（docx 段落） | 结论 | 本轮实测数据 |
|---|---|---|---|
| R1 | "{原文逐字引用}"（§8） | ✅ 达成 | {数据} |
| R2 | "{原文}"（§9） | ⚠️ 部分达成 | {数据}→详见 4.x |

**小计：✅ N ｜ ⚠️ N ｜ ❌ N**

## 三、本轮全量执行记录
| 套件 | 结果 |
（每套脚本一行：通过项/违例数/耗时）

## 四、问题项详情（需求原文 + 代码实现 + 修复建议 + 实测数据）
### 4.1 ❌ {条款} —— {结论定性}
- **需求原文**：§{n}"{逐字}"
- **代码实现逻辑**：{文件:行号，实现方式}
- **实测数据**：{loguuid 样例、违例数/总数}
- **修复建议**：①{动作} ②{长期方案}
- **责任方**：{人名/角色}，{是否上线卡点}

（每个问题项同构，🔴 代码缺陷 / 🔧 环境配置 / 🟡 口径确认 分级）

## 五、已闭环缺陷（附验证数据）
| 缺陷 | 修复 | 验证数据 |

## 六、Go 条件（上线卡点）
| # | 卡点 | 责任方 | 状态 |

## 七、线上抽验清单（Go 后 24h 内）
1. {环境不可测项的线上出口}

*原始数据：`{归档路径}`；bug 代码块详见《{关联文档}》*
```

## 2. 终审版（多轮回归后最终结论）

```markdown
# 测试反馈-{项目}-{YYYYMMDD}-终审版

## 一、一句话结论
## 二、测试概况（轮次/环境/规模表）
## 三、确认缺陷（🔴 每项：现象/代码证据/影响面/责任方）
## 四、已闭环（修复+验证数据）
## 五、待确认（🟡 口径/环境项）
## 六、回归记录总表（每轮一行：时间/环境/结果/关键变化）
## 七、Go 条件
## 八、线上抽验清单
```

## 3. Bug 补录清单（用户拿去补录 bug 系统）

```markdown
# Bug补录清单-{项目}-{YYYYMMDD}

## 已修复（N 个）
### 问题 {N}：{标题}
- **现象**：{可观察行为}
- **根因**：{代码根因，文件:行号}
- **修复**：{commit hash + 改动点}
- **验证**：{轮次+数据，"已验证"/"待验证"状态}

## 附录一：顺带修正（开发修复主问题时一起改的，建议一并补录）
## 附录二：未修复清单（⚠️ 防止误录——这些是待确认/口径项，不是 bug）
```

附录二"防误录"是关键：测试系统里把口径确认项录成 bug 会污染开发绩效。

## 常用定性标签

| 标签 | 含义 | 责任方方向 |
|---|---|---|
| 🔴 代码缺陷 | 待上线分支携带，部署即生效 | 开发改代码 |
| 🔧 环境配置 | 代码正确，配置/数据缺失 | 运维补配置 |
| 🟡 口径确认 | 实现与 PRD 字面有出入，需产品拍板 | 产品定义 |
| ⏸️ 环境不可测 | 测试环境无法构造，转线上抽验 | 测试出清单 |
| ⚠️ 伪告警 | 脚本断言缺陷，已甄别修复 | 测试修脚本并记录 |
