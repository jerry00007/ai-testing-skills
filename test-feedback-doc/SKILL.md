# Test Feedback Doc Generator

生成结构化测试反馈文档。核心价值：**每个问题项四要素齐全**（需求原文 → 代码实现逻辑 → 修复建议 → 真实测试数据），结论先行，可直接转发开发/产品/运维。

## 触发场景

- "生成一份反馈 md" / "生成反馈文档"
- "从需求出发进行大回归，生成反馈"
- "生成 bug 补录清单" / "汇总 bug 到一个文档"
- "终审版反馈" / "上线 Go/No-Go 结论"

## 文档类型选择

| 类型 | 触发 | 骨架 |
|---|---|---|
| **需求大回归版** | 用户要求"从需求出发"回归 | 需求逐条验证总表（R1-Rn）+ 问题项详情 + 已闭环缺陷 + Go 条件 + 线上抽验 |
| **终审版** | 多轮回归后的最终结论 | 一句话结论 + 测试概况 + 确认缺陷 + 已闭环 + 待确认 + 回归总表 + Go 条件 |
| **Bug 补录清单** | "帮我汇总 bug 我去补录" | 修复问题表（现象/根因/修复 commit/验证状态）+ 附录（顺带修正 + 未修复清单防误录） |

骨架详见 `references/document-templates.md`，按实际项目裁剪，不生搬硬套。

## 生成流程

1. **收集素材**（缺一不可，缺了就先跑脚本/读代码补齐）：
   - PRD 原文：从需求文档（docx 用 python-docx 提取，保留段落号便于引用）逐条摘出可测条款
   - 测试数据：本轮脚本真实执行输出（loguuid、违例数、趋势数据），禁止编造或用历史数据冒充
   - 代码逻辑：问题项对应的开发实现（文件:行号 + 走查结论），有 bug 确认报告的引用之
   - 修复状态：各问题当前的 commit / 验证轮次
2. **需求逐条映射**：PRD 每条可测条款 → R1-Rn 编号 → 结论（✅达成/⚠️部分/❌未达成/⏸️环境不可测转线上抽验）→ 本轮数据。部分达成的必须在"问题项详情"里展开。
3. **问题项详情**（核心章节，每项必须四要素）：
   - 需求原文：**逐字引用**（含 docx 段落号），不许转述
   - 代码实现逻辑：开发怎么实现的（文件:行号），为何当前行为如此
   - 实测数据：loguuid 样例、违例数/总数、多轮趋势
   - 修复建议 + 责任方（具体到人名或角色）
4. **结论先行**：文档开头一句话结论（有条件 Go / 有条件 No-Go / Go），Go 条件列表编号+责任方+状态。
5. **附归档路径**：原始数据文件路径（各轮 output 归档），供追溯。

## 写作规则（硬约束）

- **四要素齐全**：任何标 ❌/🔴 的问题项，缺任何一要素都不算完成
- **数据必须真实**：所有数字来自本轮脚本 stdout/log，标注轮次和时间戳；多轮数据给趋势（如 11→8→3→0）
- **区分缺陷性质**：代码缺陷（🔴 部署即生效）/ 环境配置（🔧 补配置即恢复）/ 口径确认（🟡 产品拍板）——修复建议和责任方完全不同，不可混写
- **回归判据必过"断言三问"**（源自104149复盘）：①该发生的是否发生了（正向）？②不该发生的是否没发生（反向）？③**该发生的全部发生了吗（完整性）**？——凡需求含量词（TOP N/前N条），判据必须是数值等式 `实际命中 == min(符合条件数, N)`，**不接受"出现X即通过"的存在性判据**；缺完整性判据的文档不允许出 Go 结论
- **未定案异常清单**（源自104149复盘）：异常现象给出"疑似X"类未验证解释的，必须列入文档强制章节"未定案异常"，**挂起超过一轮回归必须升级为独立问题单或推动日志级定案**——不允许未验证解释长期挂起导致信号灭失（反例：智界R7"疑似缓存"挂起两轮，实为语义bug信号）
- **伪告警要甄别后记录**：脚本断言失败先做对照实验定位（是产品行为还是脚本缺陷），脚本缺陷修脚本并在文档记录甄别过程
- **原文引用带出处**：PRD 条款带段落号，代码带 文件:行号，日志带 loguuid/时间戳
- **文件命名**：`测试反馈-{项目名}-{YYYYMMDD}-{类型}.md`（如 测试反馈-竖版视频组卡-20260911-需求大回归.md），同日迭代加类型后缀不覆盖
- **中文文档**：面向国内团队，标题/表格/结论全中文，loguuid/字段名/命令保留原文

## 质量自检（生成后必做）

- [ ] 每条 ❌/⚠️ 条款都在"问题项详情"有对应小节且四要素齐全？
- [ ] 所有数据能对上脚本原始输出？无编造数字？
- [ ] 回归判据通过"断言三问"？含量词需求有数值等式断言？
- [ ] 未定案异常（"疑似X"类）都列入清单且有下一轮动作？
- [ ] Go/No-Go 卡点各有责任方和状态？
- [ ] 环境不可测项都给了线上抽验出口，而不是留空？
- [ ] 文档可独立阅读：开发/产品拿到后不需要再来问上下文？
