# 输出模板 (Output Template)

生成产品经理可直接使用的反馈文档。
默认输出 Markdown + DOCX 双格式。

---

## 文档结构

```
# [需求名称] — [评审范围] 评审反馈

技术团队基于知识库+代码经验自查后，仅保留真正需要产品确认的问题。
原始 N 个问题中，M 个已自解，剩余 K 个需产品确认。

---

## 一、已自解清单（无需产品确认，仅供知会）

以下问题技术团队已基于代码知识库和经验给出明确答案：

| # | 问题 | 结论 | 依据 |
|---|------|------|------|
| 1 | [问题简述] | [具体结论] | [文件路径 §章节] |
| 2 | ... | ... | ... |

---

## 二、需产品确认的问题

### 🔴 P0 — 阻塞[开发/引擎/召回]（N项）

#### 问题1: [问题标题]

**为什么知识库答不了:**
[具体原因 — 是全新概念/纯业务决策/代码中无实现]

**需产品确认:**
- [具体问题1？选项A / 选项B / 选项C？]
- [具体问题2？]

**建议:**
[如果技术团队有建议，列出]

---

### 🟡 P1 — 影响[质量/召回效果]（N项）

#### 问题2: [问题标题]

**已知信息:**
[Phase 0 知识库中找到的相关上下文]

**仍需确认:**
- [具体问题？]

**建议:**
[技术建议]

---

### 🟢 P2 — 建议明确（N项）

[同P1格式，可简化]

---

## 三、总结

| 分类 | 数量 | 说明 |
|------|------|------|
| ✅ 已自解 | N | 基于知识库+代码经验，无需产品介入 |
| 🔴 P0 需确认 | N | 阻塞开发，建议本周内确认 |
| 🟡 P1 需确认 | N | 影响质量，建议技术方案评审前明确 |
| 🟢 P2 需确认 | N | 建议开发期间明确 |
| 原始问题总数 | N | 精简后仅需产品确认 K 个 |

---

## 四、红蓝对抗风险摘要（技术内部参考）

### 风险1: [风险标题]
- 攻击场景: [具体操作步骤/系统条件]
- 发现的问题: [具体缺陷]
- 影响范围: [影响多少用户/数据/业务]
- 严重程度: 🔴高/🟡中/🟢低
- 建议: [修复建议]

[...更多风险]
```

---

## 输出质量校验

在输出文档前，逐项检查：

- [ ] **自解清单完整**: 每个自解结论都有证据来源？
- [ ] **"为什么答不了"清晰**: 每个需确认问题都解释了为什么技术团队自己查不到？
- [ ] **"需确认什么"具体**: 产品看到后知道该回答什么？不是开放式的"请确认"？
- [ ] **P0/P1/P2 合理**: P0 不超过 5 个？P0 和 P1 的区分有依据？
- [ ] **语言无技术黑话**: 产品经理不需要查技术文档就能理解每个问题？
- [ ] **表格格式**: 数据用表格而非长段落？
- [ ] **摘要数据一致**: 总结表格中的数字与正文一致？

---

## DOCX 生成规范

使用 python-docx 生成 DOCX，规范：

```python
from docx import Document
from docx.shared import Pt

doc = Document()
style = doc.styles['Normal']
font = style.font
font.name = 'Microsoft YaHei'
font.size = Pt(11)

# 标题用 doc.add_heading(level=0/1/2/3)
# 表格用 doc.add_table(rows, cols)，style='Light Grid Accent 1'
# 正文用 doc.add_paragraph()
# 加粗用 p.add_run('text').bold = True
# 列表用 doc.add_paragraph(text, style='List Bullet')
```

输出文件名: `{需求名称}-评审反馈-{版本}.docx`
